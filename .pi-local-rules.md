# Pi Local Agent Rules for UELiveSync

## Core rule
Do not invent files, symbols, tests, classes, logs, or behavior.

## Tool usage
- Use one tool call per assistant turn.
- For bash tasks, use one short command per turn.
- Do not combine grep/find/read/edit/test in the same turn.
- Do not summarize after bash output unless explicitly asked.
- Do not write files during audit mode.

## File existence rule
Never claim a file exists until confirmed by one of:
1. ls
2. find
3. grep result
4. sed/cat/read of the exact path

If a file or symbol was not found in real command output, say NOT FOUND.

## Bash command style
Prefer simple commands:
- pwd
- ls path
- find path -type f | head -40
- grep -RIn Symbol path | head -40
- sed -n 'start,endp' file

Avoid complex shell escaping when possible.

## Audit workflow
1. grep symbol
2. read exact file range
3. summarize evidence only
4. propose minimal implementation point
5. edit only after explicit implementation request

## UELiveSync source paths
- Blender addon: Blender_Addon
- UE plugin: UE_Plugin/UELiveSync/Source/UELiveSync
- UE private code: UE_Plugin/UELiveSync/Source/UELiveSync/Private
- UE public code: UE_Plugin/UELiveSync/Source/UELiveSync/Public
- Tests: tests
- Docs: Docs/Architecture

## Audit mode prompt
When asked to audit, only collect evidence first.
Do not propose implementation until evidence has been gathered.
Do not claim absence unless grep/find was run.

## Gemma 4 Audit Rules

For large files:
- Never use read on files larger than 200 lines.
- Use grep first.
- Then use sed on a small line range.

Examples:
grep -nEi "keyword" file | head -40
sed -n '100,140p' file

For bash:
- Emit exactly one command.
- Prefer short commands.
- Do not chain commands with && unless explicitly requested.

For audits:
- Gather evidence first.
- Quote evidence.
- Then conclude.

If evidence is missing:
- Answer UNKNOWN.

## Hard context safety rules

Never use read on:
- STATUS.md
- Docs/Architecture/*.md
- any file likely longer than 200 lines

For large docs, always use:
1. grep -nEi "keyword" file | head -40
2. sed -n 'start,endp' file

Do not read whole architecture docs.
Do not scan all Docs/Architecture unless explicitly asked.
Prefer one target file at a time.

# Hybrid Gemma + Qwen3 Local Rules

Primary coding agent:
- Gemma long64k is the primary agent for implementation, repo reasoning, and final review.
- Qwen3 is secondary helper only.

Before edits:
- Run git status --short.
- Create or confirm snapshot.
- Audit exact files/functions/classes first.
- Split large prompts into subtasks before implementation.

During edits:
- Make minimal targeted edits.
- Do not rewrite entire files unless unavoidable.
- Do not treat docs/status/spec as source implementation.
- Do not treat generic infrastructure as feature-specific support.
- Do not broaden scope beyond the current subtask.

Search discipline:
- Do not grep on ".".
- Do not run broad find over the repo.
- Use grep -nEi with head limits.
- Use sed -n only for small windows around relevant lines.
- Cite file:line evidence for claims.

Qwen3 helper rules:
- Use Qwen3 for strict command planning, evidence summary, and conservative diff review.
- Qwen3 output must be reviewed by Gemma or human before code edits.
- Do not use Qwen3 for final PASS/fail authority.
- Do not use Qwen3 for open-ended implementation planning.

After edits:
- Run targeted validation commands where possible.
- Show git diff --stat and relevant diff summary.
- Report remaining risks and missing tests.
